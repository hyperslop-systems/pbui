## Workbench + linking observations

1. **Three unrelated tile-chrome skins for one component.** pbui-workbench's own demo (orange/cream `TileFrame`, A-001–A-012), pbui-ecommerce (flat black-on-white `TileFrame`, I-001–I-006), and datalab-ui (saturated color-blocked custom headers, D-001) all wrap the same conceptual "tile" but look like three different products. This is very likely the "workbench + linking are a bit off" feeling the user named.
2. **Nested boxes everywhere, no visual de-emphasis with depth.** A-011's nested-tile-in-tile stacks border+header+icon-row three times at identical weight; D-001 nests tab row → tile header → doc-badge row → verb chips with no size/contrast step-down between levels. Compare to A-005/A-007 modals, which do get lighter (shadow, no repeated border) the deeper you go — the modal idiom "de-emphasizes with depth" but the tile-nesting idiom doesn't.
3. **Header title truncation is inconsistent and can eat the link badge.** A-002's "NOTES..." (manual ellipsis suffix) vs A-010's "NOT…" (character truncation) are two different implementations; either way, once a tile is narrow, the following `PortBadge` chip in the title row (visible in A-001 at full width) simply disappears rather than wrapping or shrinking gracefully (A-002, A-004, A-010).
4. **The "active/selected" tile has no visible affordance.** A-011's `data-active` tile is indistinguishable from a non-active one — no outline, no header tint change. Worth checking whether this is by design (focus-ring only, invisible in a screenshot) or a genuine styling gap; if a user can't tell which tile is "current" without clicking, that's a usability regression, not just cosmetics.
5. **Wires didn't render in the static composition (A-012) but did in a real interaction (I-004).** Points at a mount-timing/measurement issue in the story harness rather than the WireLayer component itself, but it means any static screenshot-based review of wire styling is unreliable until that's fixed — worth a follow-up ticket separate from the visual-consistency pass.
6. **One highlight color, three meanings.** The same warm tan/yellow fill marks: a selected relation-palette row (A-007), an *acceptable* connect-mode drop target (I-002), and a *refused* connect-mode drop target (I-003). Accept vs. refuse is currently text-only; a colorblind or skimming user gets no visual cue.
7. **PortBadge states are under-differentiated.** 5 of 8 states (following/held/fixed/shared/derived) render as the same black-bordered box; only the glyph changes (A-003). Given how central badge state is to explaining what a tile is doing, more visual separation (color, weight, or icon size) seems warranted.
8. **Object-menu chrome is flatter than dialog chrome.** The right-click menu (I-001, I-006) is a plain 1px-border box with no shadow/radius, while RebalanceDialog and RelationPalette (A-005, A-007) are proper elevated cards with shadow + radius — both are "the workbench asking the user to choose something," but they look like they come from different UI kits.
9. **Menu header row style is inconsistent between two near-identical menus.** I-001 renders the "<order> #88152 …" header row in plain white/black text; I-006 (same order, different tile layout) renders the identical header row inverted (black background, white text) — looks like a stray hover/focus state rather than intended styling, but it's visually jarring side by side.
10. **CoordinationInspector uses a different "data display" idiom than everything around it** (A-001): plain unbordered PORTS/WIRES tables next to `JsonBlock`'s boxed/scrollable style in the sibling Notes tile. Worth deciding on one tabular convention for "structured debug data inside a tile."
11. **The ShowChooser dialog may be effectively unreachable from its own demo story** (A-008) — worth confirming with a real second candidate before trusting any future screenshot of it.
12. **Rebalance proposal-card diagrams use a distinct flat-rectangle visual language** (solid black / dashed / pastel-fill blocks, A-005/I-007) that doesn't reuse tile tones or the badge/chip vocabulary anywhere else — intentional "diagram mode," but worth a deliberate decision rather than an accident of two different engineers drawing two different UIs.
13. **datalab-ui's bespoke doc-badge ("α · active" solid pill) vs. pbui's `PortBadge`/`Chip` (bordered, monochrome, text-forward)** are the two clearest divergent "badge/chip" implementations found across the whole audit — folding datalab-ui's badge onto the core `Chip` (or vice versa) looks like the single highest-leverage consolidation.
14. **datalab-ui's black top/bottom command bars** have no analogue in pbui-workbench or pbui-ecommerce, which sit directly on a white page background — if datalab-ui is meant to demonstrate "workbench in a real product," its shell chrome diverging this much undercuts that as a consistency reference.
15. **Divider hit-areas are nearly invisible** (A-009): the dotted gray divider indicator is low-contrast against white, making resize handles hard to discover in a static screenshot (and, likely, for a sighted user scanning quickly).
16. **Panel/tile radius and shadow are near-zero everywhere except modals.** Every tile in A/I series is a plain 1px black-bordered rectangle, 0 border-radius, no shadow; the moment you hit a dialog (A-005/A-007) you get radius + shadow. That's a deliberate two-tier system (flat tiles, elevated overlays) but it's worth confirming it's deliberate and not just "nobody styled the tile corners."
17. **Off-palette colours are concentrated in application content, not chrome** — the chart bars in I-003 (green/purple/yellow) and datalab-ui's role-colored tile headers (D-001: purple/gold/salmon/teal) are the only saturated colors anywhere in the audit; the workbench/linking chrome itself is uniformly monochrome + one orange/cream tone pair. Consolidation candidate: agree whether tile-header color should ever carry semantic meaning (datalab-ui says yes, pbui-workbench/ecommerce say no).
18. **Badge chip font size vs. title font size mismatch** (I-005): the "#88213" pin chip reads slightly smaller/lighter than its tile's title, a small but noticeable type-scale inconsistency within a single header row.
19. **Icon-button row density scales badly with narrow tiles** (A-004, A-010): once a tile drops under ~200px, the icon buttons (⌕ ↔ ↕ ✕) visually collide with the truncated title text with no minimum-width protection.
20. **Consolidation candidate: unify "acceptable/refused" drop-target color with the object-menu disabled-row treatment.** I-006's disabled "Link to detail A" row (greyed text) and I-003's refused-port highlight (tan fill + text) are both "you can't do this right now" states but use unrelated visual languages (grey-out vs. colored-highlight-plus-tooltip).
