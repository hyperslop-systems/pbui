# Demo screenshot notes (PBUI-VISUAL-1)

Screenshots: `various/screenshots/demos/<demo>/NNN-<slug>.png`, manifests alongside.
Viewport 1440×900. Chromium via `scripts/03-screenshot-demos.mjs`.

Backends: **pbui-chat** needed its Go server — started with
`GOWORK=off go run ./cmd/pbui-chat serve --port 8090` in tmux window
`pbui-visual:backend-pbui-chat` (scripted demo engine, no model credentials
needed). **datalab-ui** needed no backend: the default route is the local
(unauthenticated "welcome" stage) workbench, which uses fixture data; `/v1`
is only touched by the remote-workbench (`?workbench=`) and device-approval
routes, neither of which the default `/` or `/ui/` path exercises. No Go
`cmd/` exists for datalab-ui in this repo, so nothing to start there.

## Cross-demo observations

1. **Masthead treatment is different in every demo but one pair.** datalab (004) and pbui-chat (001) both use a solid **black** top masthead band with white/bold text; pbui-plotscript (001) and pbui-ecommerce (001) use a **plain white/paper** top row with no colour block at all. Same design system, two incompatible "is this the top bar" languages.
2. **The launcher dialog is two different components.** datalab's "GO TO VIEW" (datalab-ui/007-008) is an inline, undimmed, non-centered panel that overlays part of the tile grid. pbui-chat/pbui-plotscript/pbui-ecommerce's "Place/Open an application" (pbui-chat/005, pbui-plotscript/005, pbui-ecommerce/005) is a centered modal with a dimmed backdrop. Datalab clearly rolled its own launcher chrome instead of the shared `pbui-workbench` one the other three use.
3. **Tile-header colour coding is applied inconsistently.** datalab colours *every* tile bar by app kind (purple/gold/coral/teal, datalab-ui/004). plotscript colours its two kinds (blue-gray SCRIPT, orange PLOT, pbui-plotscript/001). pbui-chat and pbui-ecommerce colour only the INSPECTOR tile (pale yellow, pbui-chat/001 and pbui-ecommerce/001) and leave every other tile plain white/off-white.
4. **"Gold Coin Shop" is styled two different ways across its own two demos.** pbui-chat titles it "GOLD COIN SHOP" in bold uppercase white-on-black (pbui-chat/001); pbui-ecommerce titles the same fictional shop "gold coin shop" in lowercase black-on-white (pbui-ecommerce/001). Same product name, opposite case and inverted colour treatment.
5. **Object-menu chrome is the one thing that IS consistent.** datalab-ui/005-006, pbui-chat/003-004, and pbui-ecommerce/002-003 all render the same black-background/white-text `<type> label` header row with a plain list of buttons below, danger items in red. This is the strongest positive consistency point in the set.
6. **"Link to…" (the accept/link family) only exists in two of four demos.** pbui-ecommerce (pbui-ecommerce/003) has a rich, clear "Link to X · role" menu family. datalab's doc chips (datalab-ui/006) and pbui-chat's tiles (pbui-chat/003-004) show no "Link to…" items at all in the presentations tried — either the family isn't wired for those object types, or it lives somewhere this pass didn't reach.
7. **The Rebalance dialog exists in two of four demos** (pbui-chat/008, pbui-plotscript/006) with identical chrome (two proposal cards, black/pale-blue/mint thumbnails, Apply+close / Apply / Undo). It is not wired in datalab (Mod+Shift+K did nothing observable) and pbui-ecommerce's `ShopShell` does not mount a `<Rebalance>` surface at all.
8. **The amber "READY / hover anything…" mouse-doc status bar** appears at the bottom of datalab (datalab-ui/004) and pbui-chat (pbui-chat/001) but is entirely absent from pbui-plotscript and pbui-ecommerce screenshots — two of four demos give up a full row of persistent hover/verb documentation that the other two rely on.
9. **Cell/reference boxing density varies hugely.** pbui-ecommerce boxes almost every piece of referenceable data — order ids, customer names, status pills (pbui-ecommerce/001, 009). datalab boxes structural chips (doc chips, verb buttons) but not table cell contents. pbui-chat boxes only toolbar buttons and tile titles. plotscript boxes almost nothing except the active workspace tab.
10. **Hover affordance is inconsistent.** pbui-ecommerce's port badge gets a clear dashed gold outline on hover (pbui-ecommerce/007). pbui-chat's workspace-strip button gets a pale gold fill on hover (pbui-chat/009). plotscript's tab, tile-action button, and split divider show no visible change on hover at all (pbui-plotscript/002, 008, 009).
11. **Two different golds.** The pale gold/tan hover fill in pbui-chat/009 and the mustard-gold ENCODING/CHEAT-SHEET tile-bar colour in datalab-ui/003-004 look like the same underlying token family, suggesting a shared `--pbui-tone-*` palette — good evidence the *tokens* are shared even where the *usage* diverges.
12. **Menu-item semantic colours aren't standardized.** Observed: red for destructive ("Close tile", pbui-chat/003; pbui-ecommerce/002), blue for "Connect…" (pbui-ecommerce/002 only), orange/italic for a disabled item with a reason (pbui-chat/004). No demo besides ecommerce uses blue for an action verb, so it's unclear if blue is a deliberate "this opens a picker" convention or a one-off.
13. **Empty-state copy style is a genuine strength.** "nothing inspected — choose Inspect from any object's menu" (pbui-chat/001), "no order yet … right-click one and choose 'Link to order detail'" (pbui-ecommerce/002), "no source — load one from the sources tile" (datalab-ui/004) all use the same muted-gray, second-line-hint pattern. Worth preserving as the reference empty-state idiom.
14. **Focus/active-tile outline only shows up once.** datalab-ui/009 shows a solid black 2px double-border around the focused tile; no equivalent was captured on any pbui-chat or pbui-ecommerce tile in this pass, so it's unclear whether the other demos have a focus ring at all or simply weren't caught mid-focus.
15. **The wiring/link-visualization overlay (pbui-ecommerce/006, Mod+Shift+L) is unique** — a full-canvas dim-and-annotate view connecting linked presentations with a line and captions. Nothing comparable exists in the other three demos, even though all four share the same underlying link kernel.
16. **Status-pill styling in ecommerce is state-coded by border style, not just colour** (pbui-ecommerce/001): "shipped"/"paid" get a solid black border, "hold" gets a dashed dark-red border, "cancelled" gets a muted gray border with dimmed text. This fine-grained state language doesn't appear anywhere else in the set (no other demo has a comparable status-pill taxonomy to compare against).
17. **Launcher result grouping differs even among the three that share the same dialog chrome.** datalab groups by workspace with a coloured left-edge bar (datalab-ui/008); pbui-chat groups by section label only, no colour bar (pbui-chat/005); pbui-ecommerce mixes "on screen" / "in another workspace" inline annotations per row rather than section headers (pbui-ecommerce/005).
18. **Wordmark casing is inconsistent app-to-app**: "DATA LAB" (small-caps/spaced, datalab-ui/001), "DATALAB" (no space, datalab-ui/004), "GOLD COIN SHOP" (uppercase, pbui-chat/001), "gold coin shop" (lowercase, pbui-ecommerce/001), "scripted plots" (lowercase, pbui-plotscript/001) — five different capitalization choices for five product wordmarks in one design system.
19. **Dialog close (×) button placement is consistent where the shared launcher/rebalance chrome is used** (top-right corner, small square, pbui-chat/005 & 008, pbui-plotscript/005 & 006, pbui-ecommerce/005) but datalab's own "GO TO VIEW" panel places its × in a slightly different position relative to the title row (datalab-ui/007) since it isn't built from the same `Dialog` component.
20. **Legend/swatch chips in plotscript's plot (pbui-plotscript/003) are filled, borderless squares** — the only filled-shape "chip" in the whole audit; every other chip/badge/pill across all four demos (status pills, port badges, doc chips, workspace tabs) is an outlined box with no fill. This is a real outlier worth a design-system decision (is a legend swatch exempt from the "everything is an outline" rule, or should it also be boxed?).
