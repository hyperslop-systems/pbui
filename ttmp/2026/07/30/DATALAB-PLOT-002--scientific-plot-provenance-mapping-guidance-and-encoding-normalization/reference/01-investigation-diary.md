# Investigation diary

## Goal

User request, recorded verbatim:

> do 1-4. Then Create a new ticket for:
> - Show statistical provenance and diagnostics in the inspector.
> - Guide users when a recipe needs a different mapping, such as categorical x for summary or boxplot.
> - Avoid redundant encodings such as using line for both color and facet.
> Create  a detailed analysis / design / implementation guide that is for a new intern, explaining all the parts of the system needed to understand what it is, with prose paragraphs and bullet point sand pseudocode and diagrams and api references and file references. It should be very clear and technical. Store in the ticket and the nupload to remarkable.

The requested work in this ticket is design and implementation planning. The preceding PBUI package cutover was completed and pushed before this ticket was created.

## Step 1 — Confirm the current authoring state

Inspected:

```sh
nl -ba packages/datalab-ui/src/apps/EncodingApp/EncodingApp.tsx
nl -ba packages/datalab-ui/src/components/organisms/EncodingPanel/EncodingPanel.tsx
nl -ba packages/datalab-ui/src/model/graphic.ts
nl -ba packages/datalab-ui/src/store/world.ts
```

Findings:

- `EncodingApp` derives accepted x types with recipe-specific conditionals.
- Selecting a recipe dispatches `setAnalysis` immediately.
- No compatibility assessment runs against the existing mappings.
- `EncodingPanel` repeats recipe requirements as static strings.
- The panel can request a field through `pbui.accept`, but the requirement text does not invoke it.
- Redux stores analysis and mappings independently.

Decision: introduce one declarative recipe-requirements source and a pure assessment. Do not add compatibility state to Redux.

## Step 2 — Locate scientific provenance

Inspected:

```sh
nl -ba ../plot/src/render.ts
nl -ba ../plot/src/plan.ts
nl -ba ../plot/src/stats.ts
nl -ba packages/datalab-ui/test/fixtures.test.ts
```

Findings:

- `PlotOutcome` already contains diagnostics and a `VisualPlan`.
- `VisualPlan.statistics` contains the metadata generated by each executed statistical operation.
- `StatisticalMetadata` includes grouping, measure, output schema, invalid counts, interval assumptions, parameters, OLS estimates, and density bandwidths.
- Existing PBUI fixtures already assert the expected method for each recipe.

Decision: display plot-package metadata. Do not recompute or persist it in PBUI.

## Step 3 — Inspect the plot and inspector seams

Inspected:

```sh
nl -ba packages/datalab-ui/src/apps/useTable.ts
nl -ba packages/datalab-ui/src/apps/ChartApp/ChartApp.tsx
nl -ba packages/datalab-ui/src/components/organisms/ChartPanel/ChartPanel.tsx
nl -ba packages/datalab-ui/src/apps/InspectorApp/InspectorApp.tsx
nl -ba src/components/InspectorPanel/InspectorPanel.tsx
```

Findings:

- `useDocPlot` already returns the complete `PlotOutcome`.
- `ChartPanel` shows only fatal errors directly and delegates other diagnostics to `PlotHost`.
- `InspectorApp` selects only `world.inspected`.
- The shared `InspectorPanel` explicitly supports a domain-specific `renderValue` callback.
- Inspector is singleton and non-document-bound by design.

Decision: add an explicitly inspected plot report and a typed renderer with JSON fallback. Do not make Inspector automatically track the active chart.

## Step 4 — Identify the redundant-encoding path

Inspected:

```sh
nl -ba packages/datalab-ui/src/appkit/plotAdapter.ts
```

Findings:

- The adapter includes color and facet independently.
- Analytical mappings derive group from color.
- The same field can therefore reach layers as color, group, and facet.
- Suppressing a legend alone would not remove redundant grouping and scale semantics.

Decision: implement a pure effective-encoding projection where facet suppresses an identical color mapping. Apply it before schema and layer lowering. Add an authoring transaction so new interactions do not preserve the conflict.

## Step 5 — Choose delivery boundaries

The implementation can ship incrementally because each phase adds a stable seam:

1. Pure model and tests.
2. Inspector report and stories.
3. Guided recipe correction.
4. Authoring and adapter normalization with integrated acceptance.

This sequence supplies reusable contracts before UI work and leaves no phase dependent on backend changes.

## Review notes

The main implementation risks are duplicated recipe rules, stale React state after dispatch, automatic accept loops, accidental mutation in the adapter, and loss of generic Inspector behavior. Each risk has a direct control in the design.

The design deliberately excludes:

- backend work;
- persisted diagnostic snapshots;
- PBUI-side statistical recomputation;
- automatic semantic field selection;
- a generalized constraint solver;
- changes to the plot package’s consumer-neutral mapping model.
